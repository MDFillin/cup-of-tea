# The Cup of Tea — VPN-клиент для Windows

Рабочее имя кода — PVpn (проекты и пространства имён). Всё, что видит Windows и пользователь, называется The Cup of Tea:
`CupOfTea.exe`, служба и адаптер TUN `CupOfTea`, `cupoftea-cli.exe`, папки `%APPDATA%\CupOfTea`, `C:\ProgramData\CupOfTea`
(имена — `src/PVpn.Core/Product.cs`). Значок — чашка чая (`scripts/make-icons.ps1`).

Архитектура и план MVP: [`D:\vpn\plan\client-windows.md`](../plan/client-windows.md).

## Сборка
```powershell
scripts\fetch-cores.ps1          # sing-box 1.14.4 и Xray 26.10.21 с GitHub, проверка SHA256 → cores\
dotnet build
dotnet test                      # юнит-тесты + проверка конфигов настоящими ядрами
scripts\build.ps1                # самодостаточный комплект out\CupOfTea (служба, CLI, ядра, скрипты)
scripts\build-setup.ps1          # установщик out\CupOfTea-Setup-<версия>.exe (Inno Setup 6)
```
Нужен .NET 10 SDK; для установщика — Inno Setup 6 (`winget install JRSoftware.InnoSetup`). Скрипты `.ps1` сохраняются в UTF-8 **с BOM** (иначе Windows PowerShell 5.1 ломает кириллицу).

## Что готово (этапы 0–5)
- `src\PVpn.Core` — разбор ссылок `vless://` и `hy2://`, генераторы конфигов Xray и sing-box, запуск ядер
  (конфиг через stdin, Job Object, штатная остановка через Ctrl+C), определение физического адаптера и конфликтов
  с другими VPN, маршруты, kill switch на WFP, пинг, системный прокси (WinINET), профили под DPAPI, клиент службы.
- `src\PVpn.Service` — служба CupOfTea (LocalSystem): канал `\\.\pipe\cupoftea`, TUN-сессия, kill switch, сторож ядер и связи,
  переход на новую сеть, тестовый режим с автоотключением, восстановление сети после сбоя (`CupOfTea.Service.exe --repair`).
- `src\PVpn.Cli` (`cupoftea-cli.exe`) — консольный помощник: `import`, `list`, `check`, `test`, `proxy`, `ping`, `netinfo`,
  `svc …` (управление службой), `killswitch [off]`.

## Интерфейс (`CupOfTea.exe`)
`src\PVpn.App` — WPF (.NET 10, WPF-UI, MVVM Toolkit), значок в трее, один экземпляр. Работает без прав администратора:
режим TUN — через службу, режим прокси — сам (xray + системный прокси, восстанавливается при выходе и после сбоя).
Только тёмная тема (палитра и стили — `Theme.xaml`), интерфейс растёт вместе с окном (рисуется под 1100×720).
Боковое меню: «Главная» (состояние, время сеанса, кнопка питания цвета состояния, режим, текущий сервер, скорость,
трафик и IP), «Серверы» (группы по подпискам, поиск, вставка ссылок и QR, проверка задержки), «Маршруты» (раздельное
туннелирование), «Настройки» (группами; DNS, обход блокировок, тонкая настройка TUN, доверенные сети, подписки и ядра —
своими страницами), «Журнал» (из службы, без ключей; восстановление сети, диагностика). Ярлык в «Пуске» ставит `install.ps1`.

Раздельное туннелирование — два режима со своими списками: «всё через VPN, кроме выбранного» и «через VPN только
выбранное». Программы — по exe или по папке (правило переживает обновление, например Discord), в том числе из списка
запущенных; сайты — по домену со всеми поддоменами. В TUN это правила sing-box (`process_path_regex`, `domain_suffix`)
и DNS напрямую/через туннель по режиму; применяются без переподключения (`svc reconfigure`). В режиме прокси — только сайты.
Обход блокировок (оба режима): отпечаток TLS и режим XHTTP (или «из ссылки»), фрагментация
TLS ClientHello (`tlshello`, 100–200 байт, 10–20 мс), mux для VLESS по TCP (8 потоков, xudp 16; у Vision через mux идёт
только UDP, у XHTTP — свой XMUX, его параметры можно задать), шумы перед подключением Hysteria2 (`finalmask` noise,
50–100 случайных байт) и смена портов hy2, если в ссылке диапазон (`host:20000-30000`, `host:443,20000-30000` или `mport=`;
`finalmask` udphop). Служба проверяет настройки сама; в CLI — `--bypass файл.json` (поля как в IPC: `xhttpMode`, `xmux`, `noises`…).
DNS (режим TUN): Cloudflare, Google, Quad9, AdGuard (без рекламы) или свой адрес DoH — всё по DNS-over-HTTPS через туннель;
готовые — по IP с именем для TLS, свой домен разрешается через Cloudflare тем же путём. «Проверить утечку DNS» спрашивает
bash.ws, какие резолверы видели запросы, и сверяет их с выбранным провайдером. CLI: `svc connect … --dns quad9|https://…`, `dnsleak [--dns D]`.
Подписки (Remnawave, 3x-ui, Marzban): ссылка `https://…` в настройках или через «Вставить ссылки». Список серверов — base64
или обычный (из ссылок берутся VLESS и Hysteria2, остальные пропускаются с подсчётом); трафик и срок — из
`subscription-userinfo`, название — из `profile-title`, период — из `profile-update-interval` (по умолчанию 12 ч, после
ошибки повтор через 30 мин). При обновлении серверы с тем же именем сохраняют Id, пропавшие удаляются, ручные не трогаются;
при ошибке панели остаётся прежний список. Ссылка хранится в зашифрованном profiles.dat.
CLI: `sub add <url> [--name N]`, `sub list`, `sub update [<имя>]`, `sub remove <имя>|--all`.
Полные конфиги из подписки: клиент просит у панели конфиги xray (User-Agent, по которому панели их отдают), а если панель
так не умеет — берёт ссылки. Сервер из конфига работает со своими маршрутами (geosite/geoip — базы `geoip.dat` и
`geosite.dat` рядом с xray), DNS (в TUN запросы DNS решает xray сервера), фрагментацией (`finalmask`), автовыбором
(балансировщики) и цепочками; так же работают trojan и gRPC. Служба берёт из конфига только выходы, маршруты, DNS и
наблюдение за серверами (без входов, журналов с путями, `ext:`-файлов и сертификатов с диска) и привязывает выходы
к физическому адаптеру. Раздельное туннелирование приложения — выше маршрутов сервера; «Обход блокировок» к таким
серверам не применяется; «Маршруты → Маршруты из подписки» выключает их маршруты (всё через сервер). Служебные строки
панели («Использовано 3.43/60 ГБ») показываются под подпиской. Флаги в именах — картинки Twemoji (CC-BY 4.0,
`src/PVpn.App/Assets/Flags`).
Удобство: скорость и трафик за сеанс (статистика исходящего `proxy` у xray через metrics на 127.0.0.1 — в TUN у xray
службы, порт приходит в статусе; счётчики адаптера wintun считают пакеты в обе стороны и не годятся); уведомления
у часов (подключено, обрыв, восстановлено, ошибка), когда окно не на переднем плане; глобальная клавиша
«подключить/отключить» (по умолчанию Ctrl+Alt+P); смена сервера из меню трея и двойным щелчком в списке (при
включённом VPN — сразу переключение, одиночный щелчок — только выбор); QR — показать сервер кодом, прочитать
код с экрана, из картинки или из буфера обмена; правка имени и ссылки сервера; «Сохранить диагностику» — zip на
рабочем столе без ключей, UUID, ссылок и токенов подписок.
Автоподключение и доверенные сети: при запуске и при смене сети (имена сетей — из Network List Manager, как в
«Параметрах» Windows; у Wi-Fi это имя сети, сети TUN и VPN отбрасываются по флагу физического адаптера) программа
подключается сам, если сеть не в доверенных, и отключается в доверенной. Ручное включение или выключение в этой сети
отменяет автоматику до смены сети. Перед автоподключением — проверка как у Windows (NCSI, msftconnecttest.com):
если сеть просит войти, программа ждёт; кнопка «Войти в сеть» отключает VPN (kill switch закрыл бы страницу входа),
открывает страницу входа и подключается сам, когда появится интернет. `cupoftea-cli netinfo` показывает сети и состояние.
```powershell
CupOfTea.exe --tray                                        # запуск в трей (так его ставит автозапуск)
CupOfTea.exe --snapshot ui.png --tab 3 [--sub dns] [--width 1600 --height 1000]  # разработка: окно в PNG и выйти
scripts\make-icons.ps1                                 # перерисовать значки (src\PVpn.App\Assets)
```

## Из INCY (0.4.0)
- **Профили маршрутизации** («Маршруты → Профиль маршрутизации»): напрямую / через VPN / блокировать по сайтам и IP,
  `geosite:`/`geoip:`, `GlobalProxy`, `DomainStrategy`. Готовые: «Россия напрямую», «… без рекламы», «Без рекламы».
  Формат JSON как у панелей (`DirectSites`, `ProxyIp`, `BlockSites`…): из буфера (JSON, base64, `…://routing/onadd/…`),
  ссылкой `cupoftea://routing/onadd/…` или от подписки (заголовок `routing`, строка в теле). Действует на серверы по ссылкам
  в TUN и в режиме прокси (правила в xray, домен — из SNI); у серверов с полным конфигом подписки — их маршруты.
- **Заголовки подписки:** `announce`/`announce-url` (объявление на главной), `profile-description`, `support-url`,
  `support-email`, `profile-web-page-url` (кнопки у подписки), `hide-url`, `sort-order`, `routing`, `new-url`/`new-domain`
  (переезд панели, только https), строки `#announce:` и т. п. в теле, `expire` в миллисекундах.
  Запрос с HWID (`x-hwid` — хэш MachineGuid, `x-device-os`, `x-ver-os`, `x-device-model`) для лимита устройств; выключается.
- **Серверы:** сортировка «как в подписке / по пингу / по имени», пинг при запуске и после обновления подписки.
- **Ссылки `cupoftea://`** (регистрируются для пользователя при запуске): `add|onadd|import/<адрес подписки или base64>`,
  `routing/onadd/<профиль>`; перед добавлением — вопрос. «Вставить ссылки» понимает те же пути с любой схемой.
- **Портативная версия** `scriptsuild-portable.ps1` → `out\CupOfTea-Portable-<версия>.zip`: без установки и прав
  администратора, только режим прокси, данные в папке `data` рядом с программой (`portable.txt` включает режим).

## Установка
`CupOfTea-Setup-<версия>.exe` — один запрос UAC. Файлы копирует Inno Setup, остальное делает `install.ps1`
(его можно запустить и вручную от администратора из `out\CupOfTea`): служба CupOfTea, правило брандмауэра
для sing-box, ярлык в «Пуске», доступ к службе для вошедшего пользователя. Ядра из комплекта (`cores-bundled`)
ставятся, только если они новее установленных (по ответу `version`): обновлённые в программе ядра не откатываются.
Установка под прежним именем PVpn снимается (её служба возвращает сеть), её более новые ядра и журналы службы
переносятся; серверы, настройки и автозапуск пользователя программа переносит сама при первом запуске.
Удаление (из «Приложений» Windows) — `uninstall.ps1`: служба возвращает сеть, системный прокси возвращается,
удаляются служба, правило, ярлык, автозапуск, папка программы и данные службы. Серверы пользователя остаются.
Журнал установки — `install.log` в папке программы.

## Режим TUN (служба)
```powershell
cupoftea-cli svc connect my-hy2 --test 120       # тестовое подключение: само отключится через 120 с без confirm
cupoftea-cli svc confirm                         # оставить подключение
cupoftea-cli svc status | disconnect | repair | logs
cupoftea-cli svc cores [check|update|rollback]   # версии ядер; проверить, обновить с GitHub, откатить
"C:\Program Files\The Cup of Tea\e2e-check.ps1"   # проверки приёмки при подключённом TUN
```
Обновление ядер (раздел «Ядра» в настройках или `svc cores`) делает служба: только официальные релизы XTLS/Xray-core
и SagerNet/sing-box (последний стабильный), архив — только с GitHub по HTTPS, его SHA256 сверяется с тем, что указывает
GitHub API; новое ядро должно назвать ожидаемую версию и принять наши конфиги (XHTTP, Vision, hy2 с шумами и сменой
портов, TUN с DoH и раздельным туннелированием). Прежняя версия уходит в `cores-previous` («Откатить» возвращает её).
Работающее подключение не рвётся — Windows позволяет переименовать запущенный exe; новое ядро — со следующего подключения.
Kill switch включён по умолчанию (`--no-killswitch` — без него). Пока он включён, наружу выходит только трафик через TUN,
сами ядра, loopback, DHCP и локальные сети; DNS мимо туннеля закрыт. Фильтры переживают падение ядер и службы и
снимаются при отключении, восстановлении сети или перезагрузке.

## Режим прокси
```powershell
cupoftea-cli import <файл со ссылками> --filter my-
cupoftea-cli test --all                         # внешний IP и задержка по каждому серверу
cupoftea-cli proxy my-hy2 --system-proxy        # SOCKS 127.0.0.1:10828, HTTP 10829 + системный прокси
```
Порты 10808/10809 не используются: их часто занимают другие VPN-клиенты. Занятый порт заменяется свободным.
